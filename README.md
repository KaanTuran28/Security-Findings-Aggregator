## English

Combines the JSON output of multiple, unrelated security scanners into a single risk dashboard — one table of "who's the riskiest thing in this build" instead of opening N separate reports.

## Overview

Reads any JSON file that follows a simple, tool-agnostic shape: a JSON **list** of finding objects, or a JSON **object** with a `"findings"` list, where each finding has at least a `"severity"` key (`HIGH`/`MEDIUM`/`LOW`, case-insensitive; anything else is bucketed as `UNKNOWN`). It then:

- Normalizes and tags every finding with which report it came from.
- Computes a weighted **risk score** per source (`HIGH=10, MEDIUM=5, LOW=1, UNKNOWN=2`) and ranks sources by it.
- Renders one combined Markdown/JSON dashboard: per-source summary table + a full findings table sorted by severity.

This happens to be exactly the shape every other scanner in this portfolio's `--format json` output already uses — so their reports plug in with zero adapter code — but this tool has **no code dependency** on any of them; it only consumes generic JSON. Point it at any tool's JSON output (SAST, container, cloud, DNS, whatever) and it works the same way.

## Installation

Requires Python 3.9+. No external dependencies.

```bash
git clone <this-repo>
cd Security-Findings-Aggregator
pip install -e .
```

This installs a `security-findings-aggregator` command. You can also run the script directly with `python security_findings_aggregator.py` without installing.

## Usage

```bash
security-findings-aggregator --inputs report1.json report2.json report3.json --output dashboard.md
security-findings-aggregator --input-dir ./reports --format json --output dashboard.json
```

| Flag | Default | Description |
|---|---|---|
| `--inputs` | — | One or more JSON report file paths |
| `--input-dir` | — | Directory to glob for `*.json` reports (alternative to `--inputs`) |
| `--output` | `sample_report.md` | Path to write the dashboard |
| `--format` | `markdown` | `markdown` or `json` |
| `--fail-on` | `none` | `none`, `medium`, or `high` — exit code `1` if the **combined** findings include one at/above this severity |

## CI Integration

Run every scanner in your pipeline with `--format json`, then aggregate and gate on the combined result in one place instead of writing separate `--fail-on` logic per tool:

```bash
dockerfile-security-linter --dockerfile Dockerfile --format json --output reports/dockerfile.json
cloud-iam-policy-auditor --policy iam/policy.json --format json --output reports/iam.json
security-findings-aggregator --input-dir reports --fail-on high
```

```yaml
# GitHub Actions step
- name: Build combined security dashboard
  run: security-findings-aggregator --input-dir reports --fail-on high
```

## Example Output

[`sample_reports/`](./sample_reports) contains four **real, unmodified JSON reports** generated by four other tools in this portfolio ([`Dockerfile-Security-Linter`](../Dockerfile-Security-Linter), [`Cloud-IAM-Policy-Auditor`](../Cloud-IAM-Policy-Auditor), [`DNS-Security-Auditor`](../DNS-Security-Auditor), [`JWT-Security-Analyzer`](../JWT-Security-Analyzer)) run against their own sample fixtures. [`sample_report.md`](./sample_report.md) is the real dashboard produced by aggregating all four — 11 findings across 4 sources, ranked by risk score.

## Limitations

This is a pure aggregator — it doesn't re-run any scanner or re-evaluate findings, it just normalizes and combines whatever JSON it's given. Garbage in, garbage out: if a source report's findings don't carry a meaningful `severity`, they land in the `UNKNOWN` bucket.

## Türkçe

Birden fazla, birbiriyle ilgisiz güvenlik tarayıcısının JSON çıktısını tek bir risk panosunda (dashboard) birleştirir — N tane ayrı rapor açmak yerine "bu build'de en riskli şey hangisi" sorusuna cevap veren tek bir tablo.

## Genel Bakış

Basit, araçtan bağımsız (tool-agnostic) bir şekle uyan herhangi bir JSON dosyasını okur: bulgu (finding) nesnelerinden oluşan bir JSON **listesi** veya `"findings"` listesi içeren bir JSON **nesnesi**; burada her bulgu en azından bir `"severity"` anahtarına sahiptir (`HIGH`/`MEDIUM`/`LOW`, büyük/küçük harf duyarsız; bunların dışındaki her şey `UNKNOWN` grubuna dahil edilir). Ardından:

- Her bulguyu normalize eder ve hangi rapordan geldiğini etiketler.
- Kaynak başına ağırlıklı bir **risk puanı** hesaplar (`HIGH=10, MEDIUM=5, LOW=1, UNKNOWN=2`) ve kaynakları buna göre sıralar.
- Tek bir birleşik Markdown/JSON panosu üretir: kaynak başına özet tablosu + önem derecesine göre sıralanmış tam bulgu tablosu.

Bu şekil, bu portföydeki diğer tüm tarayıcıların `--format json` çıktısının zaten kullandığı şekille tam olarak aynıdır — bu sayede raporları sıfır adaptör koduyla entegre olur — ancak bu araç bunların hiçbirine **kod bağımlılığı** taşımaz; yalnızca genel JSON tüketir. Herhangi bir aracın JSON çıktısını (SAST, konteyner, bulut, DNS, ne olursa olsun) gösterin, aynı şekilde çalışır.

## Kullanım

```bash
security-findings-aggregator --inputs report1.json report2.json report3.json --output dashboard.md
security-findings-aggregator --input-dir ./reports --format json --output dashboard.json
```

| Flag | Varsayılan | Açıklama |
|---|---|---|
| `--inputs` | — | Bir veya daha fazla JSON rapor dosyası yolu |
| `--input-dir` | — | `*.json` raporları için glob taraması yapılacak dizin (`--inputs`'a alternatif) |
| `--output` | `sample_report.md` | Panonun (dashboard) yazılacağı yol |
| `--format` | `markdown` | `markdown` veya `json` |
| `--fail-on` | `none` | `none`, `medium` veya `high` — **birleşik** bulgular bu önem derecesinde veya üzerinde bir bulgu içeriyorsa çıkış kodu `1` olur |


## Sınırlamalar

Bu saf bir agregatördür (aggregator) — herhangi bir tarayıcıyı yeniden çalıştırmaz veya bulguları yeniden değerlendirmez, yalnızca kendisine verilen JSON'u normalize edip birleştirir. Girdi çöpse çıktı da çöptür (garbage in, garbage out): bir kaynak raporun bulguları anlamlı bir `severity` taşımıyorsa, `UNKNOWN` grubuna düşerler.
